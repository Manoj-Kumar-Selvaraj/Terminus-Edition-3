The click sessionizer under /app/sessions still looks fine on a tidy one-tenant sample, but late and out-of-order events plus a process bounce leave the wrong closes, mixed tenants, or a watermark journal that moves backwards. Repair the existing Python processor; don't move session logic into another language or throw away the journal protocol. Shift notes are in /app/sessions/notes/oncall.md and the captured run log is under /app/sessions/logs.

- /app/sessions/docs/session-contract.md is binding for event-time semantics, schemas, lateness, gaps, restarts, and CLI. Knobs live in /app/sessions/config/processor.json, including catalog session_gap overlay.
- Drive work through /app/sessions/bin/run-sessions. Unknown flags, or omitting --input/--feed/--empty-check, fail with exit 2 before any journal or output touch. --input uses the contract's event-time tie-break; --feed keeps file order; --reset-output may wipe the side files, not the journal or in-flight sessions.
- Sessions are event-time, keyed by tenant and user, and half-open. Gap closes, watermark advances, and late-but-allowed vs too-late follow the contract.
- Persist /app/sessions/data/watermark.journal and open-session state across restarts so the watermark never steps backward.
- From a clean journal, a second identical run keeps the same digests for /app/sessions/output/sessions.jsonl and /app/sessions/output/late.jsonl. Empty input leaves those empty without advancing the watermark. Malformed records fail closed into /app/sessions/output/rejects.jsonl.
- Each successful run refreshes /app/sessions/data/last_run.json and /app/sessions/data/ops-report.json from the warehouse catalog. Leave /app/sessions/warehouse alone — that's the production click dump.
