Payments Ops has a restart problem in `/app/eod`. If a run is restarted after an internal posting or an external reservation, the batch can treat that payment as new work and apply the financial step again. We have also seen a held retry leave old customer or clearing files behind. Fix the restart path so the batch resumes the durable state in `/app/eod/state/payment_eod.db` instead of repeating it. Source reference is the replay identity once it has been accepted; a new source reference is new business even when the rest of the payment looks the same. Keep the existing COBOL program interfaces. The restart behavior and record layouts are documented in `/app/eod/docs/restart-operations.txt` and `/app/eod/docs/interface-notes.txt`.

Keep the existing reconciliation and close behavior in `/app/eod/docs/reconciliation-close.txt`. Every invocation still writes `/app/eod/out/reconciliation.json`. `/app/eod/out/customer_response.csv` and `/app/eod/out/clearing_submission.csv` are only valid after balanced reconciliation, and `/app/eod/out/success_authorization.json` only after close finishes. A held retry must not leave old official output behind. Re-running a partially or fully completed cycle should leave one financial result and one close result.
