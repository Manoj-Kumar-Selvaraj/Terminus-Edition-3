The EOD payment restart path under `/app/eod` is not safe once a cycle has already written financial state. We have seen reruns treat an existing internal posting or external reservation as new work, and a held run can leave downstream files that look successful. Repair the batch so `/app/eod/state/payment_eod.db` remains authoritative across fresh, partial and completed runs. An already-accepted source reference is the replay key; matching payment details with a new source reference are still new business. Keep the existing COBOL decision interfaces. The restart and record-layout notes are in `/app/eod/docs/restart-operations.txt` and `/app/eod/docs/interface-notes.txt`.

The cycle must still satisfy the finance controls in `/app/eod/docs/reconciliation-close.txt`. `/app/eod/out/reconciliation.json` is required on every invocation. Only a balanced cycle may leave the official customer/clearing publications, and the success authorization belongs to the later close, not merely to reconciliation. Re-running work that has already progressed must resume it without another financial effect or close marker.
