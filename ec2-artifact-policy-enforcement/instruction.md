The EC2 software gate in `/app/enforcer` started failing in both directions after the last AMI rollout. A scanner outage let an `apt` request through, direct `dpkg` and Maven downloads are not getting the same source checks, and a mutable container tag reused an older clean result after its digest changed. Security also found an expired exception still working, a decision permit that can be forged off-host, and no deny records in the audit journal.

Start with `notes/oncall.md` and `docs/policy-contract.md`. Keep the existing `artifactguard evaluate` and `artifactguard verify-permit` interfaces and do not change the supplied policy, scanner, or exception fixtures to make the incidents disappear. Package acquisition, container acquisition, and build dependencies must all be governed by the same policy semantics. If current vulnerability evidence cannot be established, enforcement must fail closed; valid cache evidence and exceptions have the scope and freshness rules in the contract. A permit is usable only for the exact instance/artifact/policy decision it was issued for, and every allow or deny must remain in the durable audit history across process restarts.
