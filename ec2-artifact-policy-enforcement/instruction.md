Security found that software can still enter some managed EC2 builders without a trustworthy PolicyGuard decision. Work from `/app/policyguard`; the operator handoff is in `notes/oncall.md` and the stable interfaces are documented in `docs/runbook.md`. Keep the existing `policyguard` CLI and the package, container, and dependency wrapper entrypoints compatible. All three ingress paths must use the same policy outcome: reject untrusted sources and non-immutable artifact identities, fail closed when required vulnerability evidence is missing, enforce the configured severity threshold and container-signature requirement, and return deterministic machine-readable denial reasons.

Cached decisions must never survive an artifact digest, policy generation, scanner-database generation, or TTL boundary that changes their meaning. Security exceptions may override vulnerability policy only when their artifact kind, digest, environment, and expiry all match. Allowed operations need a short-lived signed permit bound to the exact artifact and EC2 instance; tampered, expired, or replayed-for-another-instance permits must not verify. Persist every allow, deny, and exception decision in the audit journal without erasing existing history, and preserve correct behavior across separate process invocations/restarts.
